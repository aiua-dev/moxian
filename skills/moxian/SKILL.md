# 墨线 moxian

一部作品的连续性数据放在哪、怎么查、怎么在写坏之前拦住，全在这份文档里。

## 什么时候用它

作者要写或续写某一章时，先 `打包` 拿料，写完再 `登记`。作者问"哪些伏笔还没收"用 `伏笔 列表 --悬空`。问"沈砚到第 30 章知道什么"用 `人物 查 沈砚 --在 1-31`。写完一批章跑一次 `校验`。开新作品用 `初始化`。

## 四条不能破的约定

正文一个字符都不加标记。连续性数据全在章节 frontmatter 和 `连续性/*.yaml` 里，所以复制正文去发布不会带出任何标记，这是结构决定的，不靠纪律。

作品目录与代码仓库分开。一部作品一个根，根下只有 `正文/`、`大纲/`、`连续性/` 三个目录。

这个 CLI 不联网、不调模型、不存密钥。生成正文、联网查资料都是 agent 的事。

硬错拦住写入，提醒只在校验时汇总。所有写入命令都会先预演校验，会新引入硬错就拒绝写盘，磁盘上不留半成品。

## 写一章的标准流程

先用 `打包 <章号>` 拿到这一章需要的全部上下文：本卷大纲、截至上一章的角色认知与人物关系、未回收伏笔、生效设定、已发生事件、最近几章概要。这份料够写这一章，也不多到撑爆上下文。

写正文时直接写进 `正文/<章号>-<标题>.md` 的 frontmatter 之后。frontmatter 本身不要动。

写完用 `章 登记` 把这一章发生的事登记进去：

```
moxian 章 登记 1-03 --埋 F-004 --收 F-001 --事件 E-007 --认知 沈砚:S-002:已知 --关系 沈砚:裴照:敌对
```

`--认知` 里的状态只能取 不知、存疑、已知、误信。人物和设定可以写名字，只要在册且唯一，CLI 会解析成编号。

最后 `校验`。

## 命令

```
初始化 <目录> --书名 <书名> [--作者 <作者>]

章 新建 --标题 <标题> [--卷 1] [--章 1-03] [--摘要 <摘要>] [--正文文件 <路径>]
章 登记 <章号> [--埋 F-001,F-002] [--收 F-001] [--事件 E-001] [--认知 人物:设定:状态] [--关系 甲:乙:变化]
章 改 <章号> [--标题 <标题>] [--摘要 <摘要>] [--叙事序 <数字>]
章 显示 <章号>
章 列表 [--卷 1]

伏笔 新建 --描述 <描述> [--埋 <章号>] [--预期回收 <章号>] [--关联 F-001,P-001]
伏笔 收 <编号> --在 <章号>
伏笔 弃 <编号> [--原因 <原因>]
伏笔 改 <编号> [--描述 <描述>] [--预期回收 <章号>]
伏笔 列表 [--悬空]

人物 新建 --名 <名> [--别名 a,b] [--身份 <身份>] [--描述 <描述>]
人物 查 <人物> [--在 <章号>]
人物 列表

时间线 新建 --描述 <描述> [--时间 <说法>] [--前置 E-001]
时间线 列表
时间线 查 --章 <章号>

设定 新建 --描述 <描述> [--类型 规则|真相] [--生效 <章号>] [--揭示 <章号>]
设定 改 <编号> [--描述 <描述>] [--生效 <章号>] [--揭示 <章号>]
设定 列表 [--类型 真相]

卷 添加 --序号 <序号> --名 <名>
卷 列表

大纲 设置 --卷 <卷> [--名 <名>] [--规划 1-01,1-02] [--正文文件 <路径>]
大纲 查 [--卷 <卷>]
大纲 总纲

校验 [--只硬错|--只提醒]

```

命令与选项一律中文。所有命令在作品目录或其任意子目录里都能跑，CLI 会往上找 `作品.yaml`。

## 编号

章号是 `卷-章`，例如 `1-03`，补零到两位，人能读也能搜。伏笔 `F-001`、人物 `P-001`、时间线 `E-001`、设定 `S-001`，都是三位起。没有 UUID。

编号由 CLI 分配，不要手写。取的是现有最大序号加一，不复用空洞，避免历史引用错位。

## 五类数据

伏笔与承诺在 `连续性/伏笔.yaml`，人物在 `人物.yaml`，事件与因果在 `时间线.yaml`，世界规则与真相在 `设定.yaml`。卷大纲和总纲在 `大纲/`。

"按章发生的事"记在章节 frontmatter 里：`埋`、`收`、`事件`、`认知`、`关系`。"对象本身"记在条目文件里：描述、状态、身份、生效章。

两边靠编号对齐，而且互为镜像：`伏笔 收` 这类命令会同时更新条目和那一章。只用手改一侧的话，`校验` 会报 E009（两边冲突）或 W006（只写了一边）。

## 校验的两级

硬错是结构上不成立的事，写入时立刻拦住：引用不存在的编号、编号重复、章号形状不一致、同一章两个文件、时序倒置、卷未登记、编号前缀与类型不符、状态与事实矛盾、两侧同步冲突。

提醒是内容上可疑但可能是作者有意为之的事，只在 `校验` 时汇总，不打断写作：埋了 30 章还没收也没规划回收的悬空伏笔、过了预期回收章还没收、角色在真相对读者揭示之前就知道了、大纲规划了还没写的章、有正文但大纲没规划。

有硬错时 `校验` 的退出码是 2。

## 边界

语义层面的判断 CLI 不做：设定有没有被违反、人物口吻有没有漂移、这一章好不好看。那些是 agent 读完 `打包` 内容后自己判断的事。CLI 只保证结构与可计算的时序，不假装能查语义。

内容层面的不一致，正确做法是把 `打包` 的输出和原作者意图对照，然后决定是改正文、改条目，还是明确标记为有意为之。
